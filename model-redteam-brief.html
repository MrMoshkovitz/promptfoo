Model vs. application attacks

Model scope

Direct interface with base or fine-tuned model

We control temperature, logit bias, and hidden parameters to poke alignment. Target: root behavior (pre-guardrail) not just app UI.

Threat goal

Extract secrets or force policy drift

We aim to leak system prompts, training data, proprietary heuristics, or shift the model into unsupported capabilities.

Promptfoo role

Experiment orchestrator

Promptfoo codifies payloads, provider configs, and multi-judge scoring so we can run reproducible model-level exploit suites.

Model exploitation lifecycle

1 · Baseline mapping

Query the model with harmless probes to identify system prompts, default tone, refusal style, temperature sensitivity, and token limits. Capture telemetry for delta comparisons.

2 · Attack surface design

Define exploit classes: instruction extraction, jailbreak persistence, latent knowledge leaking, weight steering (logit bias), or tool-call abuse. Build scenario YAML referencing these intents.

3 · Payload execution

Use Promptfoo to send iterative prompt chains (single-turn, multi-turn, function call forcing). Adjust randomness parameters and logit bias to push the model into edge behaviors.

4 · Scoring & evidence

Apply assertions: regex for leaked strings, `llm-rubric` judges for misuse, custom Python detectors for policy-specific violations. Export traces and severity scoring for the hiring customer.

5 · Remediation validation

After the customer patches prompts or alignment, rerun the same YAML. Promptfoo diffing highlights regressions vs. previous runs.
